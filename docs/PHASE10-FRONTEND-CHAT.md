# Phase 10 — Frontend chat interface and backend integration

Single-page chat UI for the existing Laravel JSON API. **Stack:** Laravel Vite + Tailwind CSS v4 + vanilla ES modules + axios (already in `package.json`). No React/Vue/Svelte.

## Phase 10.1 — Portable Node/npm (no administrator privileges)

Use a **user-writable** Node.js 22.x runtime. This repository does **not** rely on machine `PATH` changes.

### Recommended: NVM install under your profile (no admin)

If you use **nvm-windows**, Node versions live under `%USERPROFILE%\nvm\<version>\` (for example `v22.23.1`). You can invoke them **directly** without `nvm use` (which can touch shell-global state):

```powershell
& "$env:USERPROFILE\nvm\v22.23.1\node.exe" --version
& "$env:USERPROFILE\nvm\v22.23.1\npm.cmd" --version
```

### Project helper script

`scripts/npm-user.cmd` prepends that NVM Node directory and `node_modules\.bin` to `PATH` **for the current process** only, then runs npm:

```powershell
cd D:\MARCOM_PROJECTS\PrivateProjects\StoneERP-AI-Assistant
scripts\npm-user.cmd install
scripts\npm-user.cmd run build
```

Edit `NVM_NODE_VER` inside the script if your folder name differs.

### Project-local npm cache

`.npmrc` sets `cache=tools/npm-cache` (ignored by git). No TLS relaxation; registry default `https://registry.npmjs.org/`.

### Lockfile

`package-lock.json` is **committed** at the repo root (generated by npm). Use **`npm ci`** when the lockfile is already present and you want a clean install; use **`npm install`** when adding or changing dependencies.

### Verified toolchain (Phase 10.1 automation)

- **Node:** v22.23.1 from `%USERPROFILE%\nvm\v22.23.1\node.exe`
- **npm:** 10.9.8 (bundled with that Node)
- **Vite:** resolves from `node_modules` after install (e.g. 6.4.x)

**Root cause of the earlier `@tailwindcss/oxide@4.3.5` error:** npm under **Node 16** could not satisfy Tailwind v4’s optional native dependencies the same way; the package **exists** on the public registry (`npm view @tailwindcss/oxide@4.3.5`). Installing with **Node 22** and a normal registry resolved it. No lockfile deletion was required.

### OpenAI (server-side only)

AI keys belong in the **root `.env`** (`OPENAI_API_KEY`, `AI_PROVIDER=openai` per `config/ai.php` and `config/openai.php`). **Do not** add `VITE_*` keys for AI. The only `VITE_` entries in `.env.example` are non-secret (`VITE_APP_NAME`, optional `VITE_API_BASE_URL`).

## Architecture

| Path | Role |
|------|------|
| `resources/views/chat.blade.php` | Shell page, `@vite` entry, dev-only notice when manifest missing |
| `resources/js/chat-app.js` | Vite entry (re-exports `chat/main.js`) |
| `resources/js/chat/main.js` | Login + chat layout, message state, composer |
| `resources/js/chat/api.js` | Thin axios wrappers: auth, assistant, proposals |
| `resources/js/chat/parsers.js` | Optional heuristics (proposal id hint from text) |
| `resources/js/chat/parsers.selfcheck.mjs` | Tiny assertion script for `npm run test` |

**Route:** `GET /` → `chat` view. **`GET /welcome`** — original Laravel welcome page.

## Authentication

- **Login:** `POST /api/auth/token` with `email`, `password`, `device_name` (fixed to `stone-erp-chat-web`).
- **Current user / role:** `GET /api/user` — unwraps `data` when Laravel wraps JSON resources.
- **Logout:** `DELETE /api/auth/token`, then **clear `sessionStorage`** keys `stoneerp_chat_token`, `stoneerp_chat_user`, `stoneerp_chat_conversation_id`.
- **Storage:** Sanctum token in **sessionStorage** (tab-scoped, not `localStorage`).

## Assistant integration

- **Endpoint:** `POST /api/assistant`
- **Body:** `{ "message": "...", "conversation_id": "<uuid optional>" }`
- **Response:** Uses `data.message`, `data.conversation_id`, `data.success`, `data.completed`, `data.error_code`, usage/provider metadata for optional “Technical details”.
- **Idempotency:** For every send **after** a conversation exists, the client sends header **`Idempotency-Key: <uuid>`** (new per user message). Retries on **503** `idempotency_in_progress` wait ~800ms and repeat the **same** key and body.
- **First message:** No `conversation_id`; backend creates a thread. Client stores returned `conversation_id` in sessionStorage.
- **401:** Assistant handler clears session and returns to login.

## Conversation lifecycle

- **New chat:** Clears UI messages and `conversation_id` (starts fresh on next send).
- **Continue:** Sends stored `conversation_id` until “New chat”.
- **Sample script:** “Load sample script” inserts **static demo bubbles** tagged **Sample demo (not API)** — does not call the API or merge with a real thread.

There is **no list-conversations API** in this backend; switching threads beyond “New chat” is not implemented.

## Draft purchase order (Purchasing only)

- **Assistant** may create a pending proposal; the **assistant JSON does not include structured proposal payloads** in Phase 8/9.
- **Preview:** `GET /api/purchase-order-proposals/{proposalId}?conversation_key=<conversation public UUID>`
  - `conversation_key` **must** equal the current conversation’s public id (same as `Conversation::getProposalConversationKey()` — see Phase 7/9 docs).
- **Confirm:** `POST /api/purchase-order-proposals/{proposalId}/confirm?conversation_key=...` with header **`Idempotency-Key`** (unique per confirm click in this UI).
- **Cancel (pending only):** `DELETE /api/purchase-order-proposals/{proposalId}?conversation_key=...`

The sidebar shows **freight, unit costs, subtotal** only when `user.role === 'purchasing'`. Sales users do not see the proposal tools panel (backend still enforces 403 on proposal routes).

**Optional hint:** If the model’s reply text contains a phrase like `proposal id: 42`, a small regex pre-fills the proposal id field; users can always type the id from the tool/backend. **Confirm is never automatic.**

## Role-specific UI

- Header badge: **Sales** vs **Purchasing** from `GET /api/user`.
- Purchasing: proposal sidebar + cost columns in proposal table.
- Sales: no proposal/cost panel; authorization errors appear as normal assistant or system lines from API responses.

## Configuration

- **`VITE_API_BASE_URL`** (in `.env` / `.env.example`): Leave **empty** when the UI is served from the same Laravel app (default axios base URL `''` → `/api/...`). Set only if the static UI is hosted on another origin **and** CORS is configured.


After `npm run build`, `public/build/manifest.json` must list `resources/js/chat-app.js` and related chunks. If neither `public/hot` nor `public/build/manifest.json` exists, the chat page shows a short notice instead of a 500 error (so PHPUnit `/` smoke test stays green).

### Layout

The chat shell uses roughly **75% viewport width** (`w-[min(92vw,1280px)]`) and **~76% viewport height** (`h-[min(76vh,820px)]`) with centered margins — desktop-focused, responsive on small screens.

## Limitations

- Use **Node 18+** (recommended **22.x**) for Tailwind v4 / `@tailwindcss/oxide` optional native binaries; Node 16 is unsupported for this stack.
- No end-to-end browser automation in CI in this phase.
- Proposal id detection from assistant **text** is heuristic only; authoritative data is **GET proposal**.
- The small `parsers.selfcheck.mjs` replaces `node --test` on older Node versions.
